# 《零网寻踪》沉浸式教程与终端 Help 系统设计

## 目标

修复新玩家进入序章后不知道该做什么、终端命令不可发现的问题，同时保持《零网寻踪》的桌面悬疑氛围。教程不使用悬浮任务栏、步骤清单、箭头或高亮框直接指路，而是把操作引导写进邮件、附件、文件、终端回显和通讯器内容。玩家做出正确方向的动作时，游戏用短暂窗口边框脉冲、轻量提示音和剧情内回应确认进展。

教程只教工具和调查方法，不直接提供关键搜索词、密码、结案答案或证据结论。

## 当前问题

- `TerminalCommandRouter.SUPPORTED_COMMANDS` 没有 `help`。
- 终端启动时只打印一次静态命令列表，没有语法说明、场景说明或错误恢复入口。
- 序章没有教程状态机；邮件和终端虽然同时打开，但没有检测玩家是否读信、看附件、搜索、扫描或取证。
- 现有三级提示在停滞 6、12、18 分钟后才出现，无法承担开局操作教学。
- 正确操作没有统一的感官确认，玩家难以判断是方向正确、命令仅仅执行成功，还是剧情已经推进。

## 体验原则

1. **引导属于世界内部。** 所有方向提示来自林薇的延迟邮件、离线签名盒残片、旧服务说明、终端诊断回显或通讯器恢复消息。
2. **系统确认操作，角色提示思路。** ZERO-SHELL 只确认命令效果；林薇留下的内容只说明调查方法和下一步思考方向。
3. **不展示固定目标 UI。** 桌面顶部、终端标题栏和应用窗口中不增加“当前任务”“第几步”或待办清单。
4. **正确方向有轻反馈。** 每个教程步骤首次完成时，对产生进展的应用播放一次边框脉冲和短促双音，不连续闪烁，不使用恐怖 sting。
5. **错误输入可恢复。** 未知命令给出最接近的合法命令，并提示 `help`；缺少参数时给出该命令的标准语法。
6. **不重复打扰。** 步骤完成反馈幂等，读档后不重播已经消费的消息和声音。
7. **教程可退出。** `help tutorial` 说明 `tutorial skip` 与 `tutorial restart`；跳过只关闭教学消息，不改变案件进度和三级提示。

## 沉浸式序章流程

序章的新档流程由九个顺序步骤组成。步骤文本全部存放在 `data/cases/prologue.json`，代码只解释触发条件和投递方式。

### 1. 阅读死者邮件

- 初始仍并排打开邮件和终端。
- 林薇邮件正文自然写明：先核对附件，不要把错误页当作无意义损坏文件。
- 玩家第一次选中目标邮件后，邮件窗口边框轻闪，播放低音量双音；附件区域保持普通交互，不出现箭头。

### 2. 打开附件并识别线索

- 玩家打开 `LW_最后一次校对.zlog.link` 后，查看器显示错误页和 `MIRROR-17`。
- 附件正文追加一段旧服务说明：单独的缓存号不是地址，需要和服务旧称一起核对。
- 查看器边框脉冲；通讯器收到一条“离线签名盒”恢复记录，内容只提醒组合两段信息，不写出完整搜索词。

### 3. 自由搜索

- 玩家在浏览器输入任意文本。只有命中 `kg_mirror_search` 或合法别名才完成步骤。
- 命中后浏览器边框脉冲并播放双音；结果页中的缓存监测条目自然说明该镜像仍响应网络探测。
- 错误搜索不闪边框，也不出现“答案错误”；原三级提示继续负责长时间卡关。

### 4. 扫描当前网络

- 玩家执行 `scan` 后完成步骤。
- 终端回显除节点列表外，增加剧情内诊断句：“检测到一条只读镜像响应；未知防护状态需先识别。”
- 终端边框脉冲。这里教会玩家从搜索结果转入终端，但不替玩家输入命令。

### 5. 识别节点防护

- 玩家对正确节点执行 `probe <地址>` 后完成步骤。
- `probe` 回显保留模式、锁层与追踪信息，并根据防护模式给出通用说明，例如“锁层可交由 crack 任务处理”。
- 对错误地址或缺少参数的输入不推进，直接返回带语法的可恢复错误。

### 6. 破解与反向追踪

- 正确启动 `crack <地址>` 后，终端第一次播放硬盘寻道声并进入已有异步破解流程。
- 第一个 `COUNTER-PING` 出现时，林薇的离线便签在终端恢复一句：“中继不是敌人，是你甩掉视线的出口。”
- 玩家成功执行正确的 `trace <中继>` 后完成该子步骤并获得边框脉冲；教程不降低原有追踪风险，也不替玩家自动断线。

### 7. 进入文件系统

- 破解完成后，ZERO-SHELL 输出 `ACCESS GRANTED`，随后恢复林薇的操作便签：“先看目录。文本看原文，证据复制回本机。”
- `help ls`、`help cd`、`help cat`、`help open` 和 `help get` 可解释语法。
- 玩家首次成功执行 `cd` 或在自动连接的根目录执行 `ls` 时推进。

### 8. 阅读原文并取证

- 成功 `cat`/`open` 林薇日志只确认“原始内容已读取”；不把阅读等同取证。
- 成功 `get` 关键日志后，终端与查看器中当前相关窗口只脉冲一次，播放完成音，并由通讯器投递林薇预留的最后一句：“别只记结论，保留能交给警方复核的原件。”

### 9. 结案教学

- 取得结案所需证据后，通讯器提示“本地证据目录已满足封存条件”，不自动打开报告。
- 玩家自行从任务栏进入结案报告。第一次提交问题时，报告窗口对有效提交轻闪；答错不闪红边、不播放惩罚音。
- 序章结案后教程标记完成。01 与 02 不再逐步带领，只保留全局 `help`、命令错误恢复和原三级提示。

## Help 命令设计

### `help`

显示分组后的命令索引，而不是一长串命令：

- 网络侦察：`scan`、`probe`、`crack`、`login`
- 文件系统：`cd`、`ls`、`cat`、`open`、`get`
- 风险控制：`trace`、`disconnect`
- 调查辅助：`note`
- 系统帮助：`help`、`tutorial`

底部提示 `help <命令>` 查看语法。帮助文本是 ZERO-SHELL 本地手册，不涉及当前案件答案。

### `help <命令>`

每个命令必须包含：用途、语法、何时使用、一个虚构通用示例和常见错误。示例使用 `NODE`、`RELAY`、`/path/file.log` 等占位符，不使用序章真实地址、搜索词或密码。

### `help tutorial`

返回当前已恢复的最近一条剧情内操作备忘，而不是显示步骤编号或完成清单。若教程已结束，提示玩家教程已封存，并继续使用 `help <命令>`。

### `tutorial skip` / `tutorial restart`

- `skip` 关闭当前存档的序章教学投递与进度反馈，不影响案件、恐怖强度或三级提示。
- `restart` 只重置教程步骤和已消费的教学消息，不回滚证据、节点、搜索门或案件进度；重置后根据当前案件状态跳过已经客观满足的步骤，避免要求玩家重复取证。

### 错误恢复

- 未知命令：`未知命令：hlep。你是否想输入 help？`
- 已知命令缺参数：返回标准语法和 `help <命令>`。
- 参数目标错误：保留案件运行时错误，并附加一行通用检查建议，不提供正确目标。

## 数据结构

序章新增 `tutorialFlow`：

```json
{
  "enabled": true,
  "steps": [
    {
      "id": "read_dead_mail",
      "completeWhen": {"type": "mail_opened", "target": "mail_deadletter_primary"},
      "delivery": [
        {"channel": "mail", "contentId": "tutorial_mail_read"}
      ],
      "feedback": {"appId": "mail", "sound": "progress_soft", "pulse": "soft"},
      "fallback": {"afterSec": 75, "contentId": "tutorial_mail_nudge_1"}
    }
  ]
}
```

每个步骤包含稳定 ID、完成触发器、剧情内投递内容、反馈目标和可选的短期温和提醒。`contentId` 必须引用关卡内写完的全文内容；内容校验器拒绝失效引用、空文本、直接泄露答案和重复步骤 ID。

支持的完成触发器包括：`mail_opened`、`attachment_opened`、`gate_resolved`、`command_succeeded`、`counter_trace_reduced`、`node_authenticated`、`file_opened`、`evidence_collected`、`report_answered` 和 `report_complete`。

## 运行架构

新增非 Autoload 的 `TutorialRuntime`，由主场景持有：

- `configure(case_data, case_runtime, saved_state)`：加载数据并根据已有案件状态定位第一个未满足步骤。
- `observe(action_type, target, metadata)`：接收应用与案件运行时动作。
- `step_advanced(step, delivery)`：首次完成步骤时发出剧情投递。
- `feedback_requested(app_id, style, sound)`：请求主场景触发感官反馈。
- `to_save_data()` / `apply_save_data()`：保存步骤、消费消息、跳过状态和已播放反馈。

`CaseRuntime` 继续负责案件规则，不写教程文案。各 App 只报告玩家动作：邮件 App 报告打开邮件和附件，浏览器继续报告搜索，终端把原始命令与执行结果一起发出，查看器和结案报告使用现有运行时信号。主场景统一把动作交给 `TutorialRuntime`，并负责把投递送到终端、邮件或通讯器。

存档 `schemaVersion` 升为 2，新增 `tutorialState`。读取旧版存档时缺失该字段不报错；教程根据 `resolvedGates`、`authenticatedNodes`、`readFiles`、`evidence` 和报告答案跳过已经满足的步骤。

## 感官反馈

`AppWindow` 新增非阻塞的 `pulse_feedback(style)`：

- `soft`：窗口边框在约 0.45 秒内完成两次低亮度脉冲。
- 不改变窗口位置、尺寸、层级、焦点或内容滚动位置。
- 连续事件在冷却时间内合并，避免频闪。
- 恐怖强度关闭不影响教程反馈；教程音效与 jumpscare sting 使用不同音色和方法。

`AudioDirector` 新增 `play_progress_soft()`，使用低音量短双音，时长不超过 0.18 秒。读取文件仍使用硬盘声，普通敲键仍使用键击声，恐怖事件仍使用现有 sting，三者互不冒充。

## 边界与异常处理

- 玩家提前完成后续动作时，教程记录事实；当前步骤完成后可连续跳过已经满足的步骤，但同一帧最多播放一次反馈音。
- 玩家重复执行正确命令时不重复发放消息和脉冲。
- 玩家跳过教程后仍可使用全部 `help` 命令。
- 旧存档已完成序章时直接把教程视为封存，不重新播放死者留言。
- 教程反馈不会在 C 级恐怖演出、sting 后静默或窗口隐藏期间抢占恐怖节奏；必要反馈延迟到喘息段播放。
- 不新增真实攻击命令、真实目标或可迁移的攻击参数。

## 测试与验收

### 单元测试

- `help` 包含所有支持命令且分组稳定。
- 每个命令的 `help <命令>` 都有用途、语法和通用示例。
- `hlep` 等相近输入建议 `help`，不相近输入只提示命令索引。
- 缺参数返回语法，不调用危险运行时操作。
- 教程只在满足当前触发器后推进，重复动作幂等。
- 提前完成动作可在后续自动跳步，但只请求一次反馈。
- `skip`、`restart`、v1 存档恢复和 v2 存档往返正确。

### 集成测试

- 新档可按“读邮件 → 开附件 → 自由搜索 → scan → probe → crack/trace → ls/cat/get → 结案”完成序章。
- 全流程没有固定任务面板、步骤编号或直接答案。
- 每个首次正确方向动作产生一次对应应用反馈，错误方向不产生进度反馈。
- 教程完成后进入 01，不再逐步带领；`help` 始终可用。
- 三档恐怖强度下教程反馈不改变 horror event 次数和第 39 帧行为。

### 盲测通过条件

未读设计文档的玩家能在两分钟内发现 `help`，理解邮件与附件应组合调查，独立完成第一次 `scan`，并能从反馈判断自己的方向正确；测试者不需要看到任何悬浮任务清单，也不会被直接告知关键搜索词或密码。
